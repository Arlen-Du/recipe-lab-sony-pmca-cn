# 汉化维护与上游同步指南

本项目基于 [voxivoid/recipe-lab-sony-pmca](https://github.com/voxivoid/recipe-lab-sony-pmca) 进行中文本地化适配。

## 一、架构设计理念：两层分开，各管一件事

界面上的中文由两层拼成，互不干扰：

| 层 | 文件 | 负责 |
|---|---|---|
| **字体层** | `assets/cn.ttf` + `src/com/voxivoid/recipelab/Cn.java` | 让字**画得出来**。相机固件字体没有中文字形，缺字会被画成 `.notdef`，也就是方框「口」。 |
| **词条层** | `src/com/voxivoid/recipelab/I18n.java` | 让字**看得懂**。英文原文 → 中文，在 UI 边缘拦截；未收录的词条回退英文原文，绝不崩溃。 |

为什么非要两层：**早期做法是"挑固件里有的字"** —— 用繁体或两个字以内的同义词绕开缺字（git 历史里的 `修复汉化字库导致显示不全` 就是指这件事），代价是文案受限、繁简混排，每加一句都要先查固件有没有那个字形。

内置字体之后这个约束就消失了：字画不画得出来由自带的字体决定，与固件无关，词条可以正常写简体中文。

### 字体层细节

- `Cn.font(Context)`：`Typeface.createFromAsset(getAssets(), "cn.ttf")`，静态缓存；加载失败回退 `Typeface.DEFAULT`，不崩。
- `Cn.apply(Context, TextView)`：换字体的同时**保留控件原有的字重**（`android:textStyle="bold"`、chip 数值的 `DEFAULT_BOLD`），用 `Paint.setFakeBoldText` 实现。子集没有粗体字面，而 `setTypeface(tf, BOLD)` 会经过系统字体管理器，有可能把固件那个"没有中文字形"的字体换回来——正是要避开的那个。
- `Cn.apply(Context, Paint...)`：自绘视图的全部文字 Paint（`Legend` / `MenuView` / `PromptView` / `PickerView`）。
- **出口要全**：`MainActivity` 布局里的 7 个 `TextView`、动态创建的 chip 标签与数值、四个自绘视图，以及 `HintBar`（经 `Legend`）。新增任何会显示文字的控件，都要挂上 `Cn.apply`，否则那一处照样是「口」。

## 二、内置字体：子集、覆盖率检查、再生成

`assets/cn.ttf` 是 **DroidSansFallback 的按需子集**：只带"构建当时用到的汉字 + 可打印 ASCII"，约 49 KB。

子集是死名单。新增中文后如果没有重做子集，编译、构建、运行都正常，**只是在相机上画成「口」**。所以：

```
node tools/check-font.js          # 缺失时列出字符与所在文件，退出码 1
node tools/check-font.js --text   # 输出字体必须携带的全部字符（ASCII + 用字），供 pyftsubset 使用
```

检查只看**真正会被绘制**的字符（Java 注释、XML 注释都已剔除），所以注释里写任何中文都不会误报。

重新生成子集：

```bash
pip install fonttools
node tools/check-font.js --text > out/cn-chars.txt
pyftsubset DroidSansFallbackFull.ttf --text-file=out/cn-chars.txt --output-file=assets/cn.ttf
node tools/sanitize-font.js       # 必须执行：剔除现代 OpenType 布局表(GDEF/GPOS/GSUB)，保证 Android 2.3 FreeType 2.4 兼容性
node tools/check-font.js          # 必须输出 ok，否则说明子集没盖住源码用字
```

源字体 `DroidSansFallbackFull.ttf`（约 4.5 MB，AOSP）不随仓库分发，可从 AOSP 取：

```
https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-4.4_r1/data/fonts/DroidSansFallbackFull.ttf?format=TEXT
```

返回的是 base64，用 `certutil -decode` 解码即可。

### 打包：`-A assets` 与 `-0 ttf`

`build.cmd` 与 `build.sh` 的 `aapt package` 都带了 `-A assets -0 ttf`：
- `-A assets`：将字体打包入 APK。缺失时直接报错退出，避免字形退回「口」。
- `-0 ttf`：强制**不压缩**字体文件。Android 2.3.7 的 `AssetManager` 对压缩资源无法进行零拷贝 mmap，极易诱发 Native 内存破坏与段错误，不压缩能确保机身平稳加载。

## 三、如何同步上游更新并合代码

### 推荐方法：一键同步脚本

在项目根目录下直接运行：

```bash
./tools/sync-upstream.sh
```

该脚本会自动执行以下步骤：
1. 检查工作区是否干净。
2. 自动拉取上游（`upstream`）的最新代码。
3. 执行 `git merge upstream/main`。
4. 自动执行 `./tools/test.sh` 全量单元测试进行质量门禁校验。

### 手动同步步骤（若需要）

```bash
# 1. 确保添加了 upstream 源（脚本已默认配置）
git remote add upstream https://github.com/voxivoid/recipe-lab-sony-pmca.git

# 2. 拉取最新更新
git fetch upstream main

# 3. 合并到当前分支
git merge upstream/main -m "chore: sync upstream changes"

# 4. 运行单测验证
./tools/test.sh

# 5. 推送到自己的仓库
git push origin main
```

上游改动可能带来**新的英文文案**（`Recipes.java` 的配方名、`Params.java` 的 HUD 文案、`DevTools.java` 的菜单行），它们会以英文原文显示，不会崩：按第四节的流程补词条即可。如果上游带来了新的中文字符，`node tools/check-font.js` 会点名，按第二节重做子集。

## 四、如何添加或修改汉化词条

直接修改 `src/com/voxivoid/recipelab/I18n.java`：

1. **静态词条**：在静态字典 `DICT.put("英文原文", "中文翻译")` 中增加映射。
2. **动态匹配消息**：在 `tToast(...)` 或 `tMenuLabel(...)` 中针对带变量的短语进行模式匹配。
3. **保持字数约束**：chip 上的值（`tChipValue`）控制在三字以内，否则参数条会变宽、错位——这是**排版**约束，不是字形约束。
4. **创意风格与照片效果用索尼官方中文菜单用语**，与 `Recipes.STYLE_LABEL` 保持一致，让应用和相机菜单读起来是一套词。
5. **验证**：

```bash
./tools/test.sh              # 词条与期望值（test/com/voxivoid/recipelab/I18nTest.java）
node tools/check-font.js     # 用字是否都在内置字体里
```
